## Useful control obligations

Use exact theorem kind/type checks so a caller-supplied final-budget premise, a weakened correctness statement, or a net chosen after k/p/z cannot pass under the same advertised endpoint name. The required fixed quantifier is one existential net before every k, p and unknown unit input vector; the generic E interface's finite library-height condition must remain distinct from a free aggregate-fee certificate.

Strict forged-proof controls should exercise the new final resource, full-record equality, physical and concrete-existence roots. Separately test evidence/source binding against tampering with a cost projection, omitting the read summand, mismatching retained provider values and cached values, or changing the concrete run to a different older/successor execution. Some such changes can leave an easier true proposition, so their detection belongs to source/model/type binding, not solely kernel rejection of a forged proof.

Retain both successful and deliberately failing evidence, control expectations and verifier outputs. Existing genuine log-format failure provenance and prior frozen scopes must remain untouched. A future fresh kernel/strict-control result needs its own artifact/reader binding; if hosted CI and downloaded-artifact verification are claimed, obtain and bind their actual outputs separately.

Even a successful proposed audit would certify the exact selected partial primitive model and physical statements. It would not turn omitted provider/structure/control/Nat/index/counter/memory or offline discovery work into a proved complete machine-time bound. Adding those costs requires further mathematical/source developments with explicit model definitions and execution correspondences.
