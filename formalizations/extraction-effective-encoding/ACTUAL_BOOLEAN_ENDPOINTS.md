# Actual raw cached target to Boolean/list online synthesis

Only four new mathematical modules, a new explicit check/inventory and new
reports are added. No previously sealed mathematical source or metadata is
changed. Mature C6c is imported through a normal merge; dependencies for author
feedback were copied from its explicitly sealed outputs under parent approval,
with Git/source/report/log/olean hashes recorded on D. This is not fresh rebuild
or independent kernel evidence.

`booleanRawCachedRun` eagerly caches actual raw IntegerPackets, constructs only
raw numerator/denominator expression data, and executes `wordTracedPairWord`.
The latter performs actual Boolean/list fraction operations, root programs,
chart selection, base minimum and stopping comparisons, retaining each executed
evaluation/decision record once. Its entire ArithmeticWordResult is proved equal
to the preceding raw integer program's result, not merely to its semantic value.

`booleanTargetDescriptorRun` actually runs the existing target raw expression
provider once per cache precision, stores its value/root-annotation record, and
passes the stored raw packets to that online Boolean evaluator. Gate-library
raw packets are likewise eager cached. The provider root annotation is returned
as a separate field from online Boolean actions.

The actual descriptor-derived represented budget is O(C(n,L)*(k+3)^7*(q+1)^137)
and its AST operation count is O(O(n,L)*(q+1)^64). Internally applying C6c's
Boolean/list evaluation and decision model gives the exact closed coefficient
`actualBooleanDescriptorCoefficient n L k` times `(q+1)^338` (2*137+64).
No opaque runtime/height/final-complexity certificate is assumed.

`booleanCompileWord` explicitly executes and stores each single-gate program
once; word output and annotations read that same stored result. It never maps a
synthesis callback again merely to calculate a fee. The online Boolean actions
and target-provider root actions are separate coordinates and are never added
together. The final native-triple descriptor generator is also evaluated once,
with its actual rank-work fields preserved in `nativeBooleanExtractionRun`.

The entire final finite-label word equals the previous native compiler word,
and the original-register all-input Bell/discard fidelity theorem follows.
The actual returned annotation bounds are:

- rank generation: the preceding construction/filter/Nat-equality bounds;
- online Boolean/list numeric actions:
  `actualGatePolynomial k * actualBooleanDescriptorCoefficient n L k *
   (logarithmicPrecision k p+1)^338`;
- target-provider root-only annotation:
  `actualGatePolynomial k * rawProviderCachePolynomialConstant L * (k+3)^8 *
   (logarithmicPrecision k p+1)^18`.

Here `logarithmicPrecision k p = p+21+9*clog2(k+3)` bounds the actual per-gate q.
These are distinct specified source models, not a total runtime sum.

Remaining costs are explicit: converting literal Int/Nat/Rat data to Bool words
(the current evaluator uses Nat.bits adapters), provider execution beyond its
root annotation, fixed-library provider execution, packet/expression/cache
construction and lookups, list/record allocation, native selector/rank/Gray/
swap/wiring generation work outside the rank annotations, output concatenation
and serialization, numerical control/list traversal and index implementations,
root fuel/counter computation and annotation maintenance not counted by the
Boolean primitive model. No full provider Boolean bound or Turing bit-time
statement is made. The fixed library remains an effective provider contract.
