ACTUAL PACKED GRAY DECISION / REVERSE EXECUTION

New same-run path:
 scannedGraySerializedRun
  -> scannedGrayDescriptorRun/compression/stage/occupation
   -> same actual Boolean mask/plan context and accepted occupation table
   -> grayStoredLettersBranchTableRun
    -> grayListIndexedCandidateRun retains endpoint and mass once
    -> scannedEntryCompileProgram directly reads those original PackedBits
     -> scannedPreparedRotationProgram calls packedGrayScanProgram once
      -> two packedListProjectionProgram records read x.1 and y.1
      -> synchronized booleanGrayScanProgram returns first/others
     -> actual same none/some decision controls A versus A+B for the tail
     -> same stored forward/adjacent words and actual reverse-map result
   -> grayStoredLettersAlignmentRun
    -> stored endpoint/swap stack once, then scannedPreparedSwapProgram once
     -> same actual packed-list decision and reverse-map records retained
  -> same generated word to retained target/numeric/read/assembly/materializer
  -> actual same label word to binaryLabelStream

There is no old differingWire/otherWires Finset filter/minimum/erase/sort on
this runtime path. Their occurrences are proof-side specifications only.
The new packed entry compiler also avoids executing a separate old packed
endpoint equality guard before this scan. Scanning's finite Boolean/list
none/some result actually controls the mass update used by later merges.
Whole public common generation and terminal records are preserved, not cost
records reconstructed from equal mathematical words.

PackedBits is pinned Mathlib List.Vector. Vector.toList is definitionally v.1,
verified byte-for-byte against Mathlib pin d13f23b7 (SCANNED_GRAY_API_NOTES.json).
The new projection program directly retains x.1 with a local projection record;
there is no hidden bit-copy, Nat.bits or function-to-vector reconstruction.
The n-bit inputs already exist in the actual endpoint/swap-stack execution.
Their earlier construction costs keep their previous explicit boundary.

Actual local model:
- scan: at most 5*n+1 Boolean/list/record actions; untouched wire tails are
  shared and only equal-prefix wires are reconstructed
- two retained packed-list projections: one local record/projection action each
- reversal: actual listReverseMapIntoProgram, exactly 4*forward.length+1
The reverse program is actually called even for an empty forward word; that
terminal action is included. The forward word appears in the emitted word,
so its length bounds this particular actual reversal trace. Summing actual
entry/alignment records gives the internally derived Gray polynomial.
This accounts precisely for these specified local record/list primitives;
Fin payloads/pointers are not thereby made finite-alphabet machine atoms.

Remaining costs are explicitly outside this partial sum:
- List.finRange Nat construction/control and Fin payload/index bit work
- preparedMoveCode's stored-function indexed reads, equality decisions and
  Function.update states; selected-phase parity/index evaluation and general
  AST construction/append, wire prefix/shift/cast/Bell adapters
- actual packed swap-stack Equiv.swap endpoint comparisons; remaining Nat
  count/rank/erasedTriple/mass/precision/width/clog/fuel/control arithmetic
- allocation/sharing/GC, generic wrapper spines and bookkeeping not explicitly
  covered by these traces, fee/counter arithmetic and host Lean runtime
- decoder execution time, fixed-library provider time, inverse-label provider
  and offline finite net generation
All earlier included target/numeric/read/assembly/serialization partial models
remain unchanged, and only actual additional same-run records are added.

The terminal is executable, its actual decoded Bool stream has all-input
fidelity on the original registers, and specified same-run partial primitives
have a uniform polynomial. Full compiler bit/Turing running time is still open.
