# Resource model and exclusions

The compiler has executable finite syntax and finite labels relative to its supplied entry oracle. Total computability requires computable entry access, as assumed by the frozen manuscript; a numerical approximation condition alone does not imply computability. Noncomputable matrices occur in its mathematical denotation, not its returned finite word. Exact equality of complete words transfers the previously proved original-register length, error and fidelity statements, including the same physical discard.

`SingleCode.rawPacketExpression` uses actual occupation-count fractions encoded through integer numerator and denominator fields, fixed rational constants, half-angle and phase expressions. Its integer evaluator returns the entire same packet as `rawPacket`. The raw embedding still uses denominator-one rational literal DATA; its casts and construction are not free machine operations. A raw packet has AST operations 20, not the older opaque packet-literal value 1. New raw-operation recurrences feed the p64 operation bound. Integer height bounds have exponent 137. These are represented operand/AST bounds, not elapsed time.

The shared integer evaluator stores tuple children and selection scores in vectors, reads binary operands once, and evaluates only the selected branch. The shared binary-root primitive stores its numerator, division fuel, quotient, root fuel and result, avoiding an extra division solely to compute its annotation. The annotation charges the specified binary-root value subprograms. It excludes automatic fuel calculation, ordinary arithmetic/comparison, counter arithmetic, syntax construction, indexing, allocation and memory access. It is not a complete operational counter.

`targetProgramDescriptorRun` stores each actual target-provider precision record once in a vector. Its `rootCharge` is exactly the sum of those stored target-provider root annotations and the online shared numerical root annotation. The target-cache bound has exponent 18; the online bound has exponent 201. Their whole-word bound uses the actual descriptor count and the logarithmic precision derived from its actual length. The external fixed-library provider `entry` remains outside both charges, including any roots it computes.

The provider condition `DyadicQApproximates entry G` specifies approximation and output values, not the time to compute them. Even computable providers may take super-polynomial time. Input bit-width bounds measure storage, not provider computation. A future polynomial bit-time contract must bind a concrete provider algorithm, its input/output encoding and a machine execution bound for every precision, with constants depending only on the fixed library. A valid relative cost term retains all actual precision requests, repeated per descriptor unless a global cache is actually implemented. A concrete efficiently computable algebraic library is an alternative, but is not established by this profile.

Stored-swap annotations count traversed swaps, excluding endpoint equality/bit cost and the rest of descriptor generation. Counted descriptor fields charge only the stated cons/append model, excluding Nat bit work, list-length and counter computation, parser execution and input generation. CountedEnumeration and unused Boolean-word arithmetic are not imported by the selected entries and remain outside this scope.

The fixed finite net/table is an explicit nonuniform constant. No efficient uniform table finder is claimed. No full compiler Turing/bit-time theorem follows from these partial charges. The frozen 459-root manuscript states total computability and leaves classical bit time open; this new resource profile neither rewrites nor upgrades that claim.
