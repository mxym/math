# Final-copy runner trust-boundary review

Scope: review of the public v2 package whose archive SHA-256 is `add152175863fb929ecf58510bb48ff9fc8be7e234fe45d72953e56333355b2c`. This is an independent local engineering/verification review, not new mathematical research, a human referee endorsement, or an audit of a later Main candidate. It makes no GitHub changes.

## Findings

No blocking defect was found in the inspected public runner and package-integrity boundary. Full compilation/replay results are separately recorded in the final audit report; this document describes what those checks mean.

- The initial trusted Python boundary consists of the externally authenticated entry point, the standard Python/runtime environment, and `release_integrity.py`. The non-TCB `source_inventory.py` is imported only after successful `validated_snapshot(ROOT)`. An independently injected top-level sentinel, even with freshly recomputed ordinary outer seals, was rejected without execution under both normal and optimized Python.
- The inventory is fixed in the validator, and the required payload inventory has its own fixed digest. The ordinary current manifest and checksum records cannot by themselves authorize changed source, provenance, helpers, controls, or documentation. The required inventory intentionally excludes its own digest file, the validator, and the two outer seals to avoid circular hashing. Authenticating the complete archive externally remains essential.
- Duplicate JSON keys, nonfinite JSON, extra or omitted files/directories, source symlinks, special files, noncanonical paths, incomplete checksum coverage, and coordinated ordinary resealing are rejected. `require` raises exceptions rather than relying on Python assertions, so `-O` does not disable it. The only runtime-directory exclusion is a real `.git` directory.
- The packager consumes the exact already-validated byte snapshot; it does not reread unchecked source replacements or regenerate seals. It writes deterministic regular-file tar members with normalized metadata, creates a temporary output, and replaces the destination only after successful validation and archive creation. Long names use canonical path-only PAX records.
- The release runner validates the entire package before loading helpers or creating output, checks the exact toolchain-file inventory hashes, checks all nine dependency Git heads and tracked cleanliness, and compares the full 4,745-record import/source closure to the independently audited one.
- External artifact families are accepted only when all present relevant artifact suffixes match the stored family, with package/source linkage also checked. Missing or mismatched non-toolchain families are rebuilt from the pinned source graph into the new overlay; toolchain mismatches are fatal. This audit independently recomputed all 4,620 families from the original independent audit's actual artifact resolution and obtained exact equality for 27,651 artifacts. It also confirmed that the actual toolchain library contains no owned Entry005/Mxym/OAI namespace.
- `LEAN_PATH` is explicitly replaced with the new owned directory, the authenticated toolchain library, and the newly constructed external-only overlay. The old owned libraries supplied as optional cache roots are not placed on `LEAN_PATH`, and only graph records whose package is not `owned` can be selected from those roots. All 125 owned modules are unconditionally compiled into an initially nonexistent output tree, in dependency order. Each owned import must already be a fresh regular output. There is no resume, successful-log shortcut, or owned-cache fallback.
- Frozen source inventory establishes the 850 public names; the Lean public and whole-owner programs independently collect the actual declarations. The full 1,849-declaration owner inventory checks types, kinds, safety/partial flags, owners, and allowed axiom sets. Public ownership is cross-checked against actual theorem declarations.
- The frozen replay program gathers all owned roots and recursively referenced declarations, rejects unsafe/partial nodes and non-allowlisted axioms, invokes the pinned Lean replay API on `mkEmptyEnvironment 0`, and checks every root's type and universe parameters against the original. Its malformed-proof negative control exercises rejection by the same replay API. This is substantive kernel replay, not a success inferred only from importing an `.olean` or reading historical logs.
- Final source-byte equality is revalidated after all checks. Warning/error output or a mismatched exact count/inventory prevents final success.

## Explicit limits

1. Internal checksums do not authenticate a coordinated replacement of validator plus all records. The external archive hash is the authentication anchor.
2. The documented model is a quiescent local filesystem and trusted Python, operating-system commands, and pinned Lean runtime. It is not an adversarial filesystem sandbox. Parent-component symlink changes and concurrent mutation are not solved by last-component `O_NOFOLLOW` or snapshots.
3. Existing exact external dependency artifacts are reused by hash. This is not a fresh rebuild of all of mathlib, a compiler-correctness proof, or independent authentication of the entire surrounding machine. Empty-kernel replay rechecks the selected logical declaration closure using the pinned kernel implementation.
4. The source scanner is intentionally checked against this fixed frozen source inventory; it is not claimed to parse every possible Lean program. Frozen Lean controls and actual declaration inventories supply the stronger semantic checks for this package.
5. The network bootstrap wrapper is reviewed but was not executed in this final-copy audit. The supported offline exact-dependency route is the one actually exercised.
6. The checkpoint proves the literal truncation sharpness target only. The prescribed upper `Entry005.sharpMainGoal` remains open in this package, and no later Main candidate is included.
